# Client Control для OPNsense и TING

[![GitHub-only review](https://github.com/Omnividente/opnsense-client-control/actions/workflows/github-review.yml/badge.svg)](https://github.com/Omnividente/opnsense-client-control/actions/workflows/github-review.yml)

`os-client-control` — плагин для управления доступом и скоростью отдельных клиентов сети. Он хранит понятный список групп, клиентов и их IP/MAC-адресов, а затем создаёт штатные объекты OPNsense: псевдонимы, правила межсетевого экрана и ограничения Traffic Shaper.

Плагин не меняет трафик сразу после сохранения формы. Сначала администратор проверяет список изменений, затем отдельно применяет его.

## Что умеет

- группы с разрешённым или заблокированным доступом;
- работа без лимита, отдельный лимит для каждого клиента или общий лимит на группу;
- отдельные скорости загрузки и отдачи;
- индивидуальное исключение для одного клиента;
- несколько IPv4, IPv6 и MAC-адресов у клиента;
- перенос нескольких клиентов между группами;
- импорт существующих псевдонимов без изменения источника;
- показ доступности клиента, открытых соединений и состояния правил;
- проверка точного списка изменений перед применением;
- обнаружение ручных изменений в созданных объектах OPNsense;
- откат конфигурации при ошибке применения;
- журнал действий.

## Проверенная платформа

| Компонент | Проверено |
|---|---|
| Продукт | TING `1.14.6_1` |
| OPNsense ABI | `24.7` |
| FreeBSD | `14.1`, ABI `1401000` |
| PHP | `8.2.24` |
| Архитектура | `amd64` |
| Плагин | `os-client-control-1.1` |

Готовый пакет привязан к ABI системы, на которой он собран. Пакет для `24.7` нельзя считать подходящим для `25.x` или `26.x`. Для другой версии нужен новый билд на целевой системе и повторная проверка установки, страницы управления, применения правил и реального трафика.

Исходники содержат совместимость со старым и новым способом построения таблиц MVC, но это не заменяет проверку остальных API OPNsense. Версии `25.x` и `26.x` пока не заявлены как проверенные.

Подробная установка, первый запуск, обновление и ограничения: [docs/USAGE_RU.md](docs/USAGE_RU.md).

Независимая проверка без локального доступа — только через GitHub web UI, Actions, pull requests и issues: [docs/REVIEW_PLAN_RU.md](docs/REVIEW_PLAN_RU.md).

## Быстрая установка

Обычный путь — сборка прямо на целевой TING/OPNsense и установка полученного пакета:

```sh
./tools/deploy.sh root@opnsense-host
```

При входе по паролю скрипт использует `SSHPASS` из окружения. Пароль не передаётся в аргументах команды и не хранится в репозитории.

Скрипт:

1. проверяет версию и архитектуру цели;
2. собирает пакет штатным набором OPNsense plugins;
3. проверяет пакет и контрольные суммы;
4. сохраняет пакет для отката;
5. устанавливает новую версию;
6. перезапускает `configd`;
7. проверяет состояние плагина;
8. при ошибке возвращает предыдущий пакет.

По умолчанию ожидается ветка `24.7`. Другая строка версии задаётся только для отдельной проверки исходников:

```sh
TARGET_VERSION=26.7 ./tools/deploy.sh root@test-host
```

Это снимает только проверку номера версии в скрипте. Совместимость самого плагина такой командой не подтверждается.

## Первый запуск

Откройте **Межсетевой экран → Клиенты**.

1. В настройках выберите сети клиентов и интернет-интерфейсы.
2. Оставьте режим **Только проверка**.
3. Создайте группу.
4. Добавьте клиента, его группу и первый IP- или MAC-адрес.
5. Откройте **Проверка и применение**.
6. Нажмите **Проверить изменения** и прочитайте список.
7. Примените изменения.
8. После проверки переключите режим на **Применять правила**, снова проверьте список и примените его.

## Важные правила безопасности

- Новая установка выключена и не меняет трафик.
- Сохранение групп и клиентов не перезагружает правила.
- Применяется только тот список, который был показан для текущей версии настроек.
- Плагин меняет и удаляет только свои объекты с подтверждёнными признаками владения.
- Чужие псевдонимы при импорте только читаются.
- Ручное изменение объекта плагина считается конфликтом и не перезаписывается молча.
- Ошибка применения возвращает предыдущую конфигурацию и повторно загружает правила.

## Независимая проверка через GitHub

Проверяющему не нужны локальный клон, терминал, SSH или доступ к компьютеру автора. Workflow **GitHub-only review** на GitHub-hosted runner проверяет синтаксис, XML, shell-сценарии, модельные тесты, переводы и соответствие сгенерированных файлов.

Граница проверки принципиальна: зелёный GitHub Actions check не подтверждает установку на TING/OPNsense, загрузку firewall/IPFW, реальный трафик, скорость или откат. Эти пункты в независимом отчёте отмечаются как требующие runtime-стенда.

Для review issues отдельный workflow сравнивает фактического автора issue с identities проверяемого commit, pull request и Actions run. Он помечает self-review автоматически; обязательные поля формы сами по себе не считаются доказательством независимости.

## Проверки

Локальные проверки PHP, модели и переводов:

```sh
php tests/run.php
```

Проверки на установленной системе:

```sh
pkg check -s os-client-control
configctl clientcontrol health
configctl clientcontrol runtime_guard
configctl clientcontrol schedule
```

HTTP API smoke-тест меняет конфигурацию и предназначен только для отдельного тестового шлюза. Требования и переменные окружения указаны в [docs/USAGE_RU.md](docs/USAGE_RU.md).

## Структура репозитория

- `src/` — файлы плагина, устанавливаемые в OPNsense;
- `translations/` — исходный русский перевод;
- `tests/` — проверки модели, контроллеров, перевода и HTTP API;
- `tools/` — сборка, установка и удаление старых артефактов;
- `docs/` — инструкция и GitHub-only план независимой проверки.

В репозиторий не входят собранные `.pkg`, временный каталог `.build` и локальные данные доступа.
